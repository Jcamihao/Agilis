# Release Notes - v1.1.0 (Agilis)

Esta release expande o Agilis com um conjunto amplo de módulos de gestão colaborativa — OKRs, campos customizados, wiki interna, formulários de intake, portal do cliente, aprovações de tarefas e chat em tempo real — além de refatorações internas de infraestrutura (Redis, filas e e-mail) que preparam o backend para crescer sem quebrar contratos existentes.

## Destaques

- Novos módulos de produto: OKRs, Custom Fields, Wiki, Intake Forms, Client Portal e Task Approvals, todos com models Prisma dedicados e migrations próprias.
- Chat em tempo real via WebSocket Gateway, com presença de usuários (online/away/offline) centralizada no RedisService.
- Editor de texto rico (Tiptap) integrado ao frontend para a Wiki, com suporte a tabelas, imagens, links, listas de tarefas e formatação avançada.
- Refatoração de constantes compartilhadas (`queue.constants.ts`, `redis.constants.ts`) para eliminar dependências circulares entre módulos.
- Adapter "noop" de e-mail, permitindo rodar o backend em ambientes sem `RESEND_API_KEY` configurada sem falhar no boot.

## Backend

- Novos módulos registrados no `AppModule`: `ChatModule`, `OkrsModule`, `WorkloadModule`, `CustomFieldsModule`, `WikiModule`, `IntakeModule`, `ClientPortalModule`, `ApprovalsModule`.
- Novos models e enums no `schema.prisma`: `Objective`, `KeyResult`, `KeyResultTask`, `CustomField`, `CustomFieldValue`, `WikiPage`, `WikiPageRevision`, `IntakeForm`, `IntakeSubmission`, `ClientPortal`, `TaskApproval` (com enums correspondentes de status).
- Novas migrations: OKRs, custom fields, wiki, intake forms, client portal, task approvals e uma correção de FK polimórfica do health score.
- `ChatService` passa a delegar presença de usuários ao `RedisService` (`setPresence`/`getManyPresence`), removendo lógica duplicada de TTL.
- `MailModule` ganha `NoopMailAdapter`, usado como fallback quando não há `RESEND_API_KEY` configurada.
- `AuthModule` não importa mais `RedisModule` diretamente (já é global), reduzindo acoplamento.
- Constantes de fila (`QUEUE_MAIL`, `QUEUE_WEBHOOK`) e do Redis (`REDIS_CLIENT`) movidas para arquivos `*.constants.ts` dedicados, quebrando ciclos de import entre `queue`, `mail` e `webhooks`.

## Frontend

- Novas telas e serviços correspondentes a cada módulo novo do backend: Approvals, Client Portal, Custom Fields, Intake Forms (interno e público), OKRs, Wiki, Workload, Health Score, Insights e Project Settings.
- Editor de texto rico via `@tiptap/*` e `ngx-tiptap` para a Wiki (tabelas, imagens, links, highlight, task list, text-align, underline).
- Painel de chat (`chat-panel`) e componente de aprovações (`approval-panel`) adicionados como componentes compartilhados.
- Novas rotas em `app.routes.ts` para todas as features acima.
- Ajustes de UI em Dashboard, Kanban, Sidebar, Main Layout, Members, Webhooks e demais telas para acomodar as novas funcionalidades e navegação.
